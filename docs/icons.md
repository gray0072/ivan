# Arrows and icons: drawn, never from a font

Part of the repo's rules, kept out of `AGENTS.md` because not every session needs it. **Read it in full before adding an arrow, a symbol or an emoji to a text, a CSS `content`, a canvas or a texture, and when creating a game or a new screen**; `AGENTS.md` only sums it up.

- **Arrows and icons are drawn, never shown from a font.** A Unicode arrow or symbol (`→ ← ↑ ↓ ↩ ▶ ☰ ✓ ✈`) or an emoji (`🪙 🔊 📊`) comes from whatever font the device has: on a phone an arrow sits low or comes out thin, each phone shows it differently, and an emoji newer than the phone is an empty box. So every game loads the Icons engine first (`data/icons.js`, `core/icons.js`; in a project without those folders `icons-data.js`, `icons.js`): type the character in the code or a translation as usual, it stays the token, and a watcher turns it into an SVG in every text on the page as it appears, in the text's colour for a one-colour sign and sized by the text. After adding a character, a new game or a game's new screen run `node tools/icons-build.js <folder>` and bump `?v=N` of what it says changed; a new emoji is fetched once from Twemoji into `tools/icons/color/`, a sign with no emoji goes into `tools/icons/mono.js`; `--check` changes nothing and fails when something is out of date. The engine reaches only text in the page, so three places are done by hand and the tool stops on the first two: a CSS `content` is a mask (`--sign` in `world-aviation/styles.css`), a canvas calls `Icons.draw` or `Icons.drawText`, and a texture built once draws its own shape, as the image may not have loaded yet (`dirSignCanvas` in `world-aviation/render/airport3d.js`); an SVG `<text>` and an `<option>` keep plain text, so no such character goes there. Punctuation and maths every font has stay text (`× − — ≈ « »`), and so do tooltips and whatever the player does not see. Never read the `innerHTML` of a text with a sign in it: read `textContent`, which stays as typed. A screenshot from this machine does not catch a font's glyph, Chrome on Windows draws them well: check the code too.
