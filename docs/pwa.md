# Icons, installable apps, updates and offline

Part of the repo's rules, kept out of `AGENTS.md` because not every session needs it. **Read it in full before touching an icon, a manifest, the `<head>` links, `update.js`, a service worker or `tools/sw-build.js`, and when creating a game**; `AGENTS.md` only sums it up.

- **Every project has an icon.** Each project folder contains an `icon.svg` (square 512×512 viewBox, rounded-tile style with `rx="112"`, readable at 16–32 px, matching the game's theme). It is used as the page favicon (`<link rel="icon" type="image/svg+xml" href="icon.svg?v=N">`), next to the title in both project READMEs, on the project's card in the root gallery, and in the root README game table. The repo-level icon and social preview live in `assets/`.
- **Every app is an installable PWA with a crisp Android icon.** Whatever gets deployed to GitHub Pages — every project and the root gallery itself — must be installable to a phone's home screen:
  - `manifest.webmanifest` in the folder (root gallery: at the repo root) with `name`, `short_name` (≤ 12 chars, fits under the launcher icon), `description`, `start_url` / `scope` = `"./"`, `id` = the folder's absolute path (`"/ivan/<folder>/"`, the root gallery `"/ivan/"`), `display` (`fullscreen` for games, `standalone` for the gallery), `theme_color` / `background_color` matching the page background, and three icons: `icon-192.png` + `icon-512.png` (`"purpose": "any"`) and `icon-maskable-512.png` (`"purpose": "maskable"`), all with `?v=N`.
  - **`id` is the one absolute path in the repo, on purpose.** A relative `id` resolves against the *origin* of `start_url`, not the manifest's folder: `"./"` makes every app on `gray0072.github.io` the same app, `https://gray0072.github.io/`, and Android then refuses to install the second one or updates the wrong one. `start_url` and `scope` resolve against the manifest's folder, so they stay `"./"`.
  - **A new deploy reaches an app left open, but never interrupts it.** Every project (and the root gallery) loads its own copy of `update.js` (`core/update.js`; `assets/update.js` for the gallery) before the main loop and calls `AppUpdate.watch(() => <idle>)` once, where `<idle>` is true only on the start screen / menus — never during a game, a flight, a task, a pause, a dialog or a result screen. On every return to the foreground and once an hour it fetches the page's `index.html` and compares its `?v=N` links and inline blocks with the running page's; a new version reloads the page at the next idle moment. This is why the `?v=N` bump below matters twice: it is also how a running page notices the update.
  - **Every app works offline.** Each project folder (and the repo root, for the gallery) has a `sw.js`: a service worker that keeps every file the app needs in Cache Storage, so an installed app starts and plays without a network after it has been opened once online. `update.js` registers it (`AppUpdate.watch`), and the gallery also installs every game's worker a few seconds after it loads (`assets/gallery.js`, skipped in data-saver mode), so a game started from the gallery works offline even if it was never opened. The page comes from the network first (the cached copy when offline or after 4 s), a `?v=N` file from the cache (a new N is a new file), a file without `?v` from the cache and refreshed for the next start. `sw.js` is **generated, never edited by hand**: `node tools/sw-build.js` writes every app's `sw.js` from `tools/sw-template.js` with the app's file list (the docs, `tools/`, `docs/`, `supabase/`, the screenshot and `icon-maskable.svg` left out; files the page links with their `?v=N`) and a `VERSION` hashed from the files' contents — the new version is what makes the browser download the app again after a deploy. **Run it after every change to an app's files, before committing** (`--check` changes nothing and fails when a `sw.js` is out of date). A file the app needs that the tool leaves out (one in an excluded folder) still works online but not offline. The root gallery's worker serves only its own files: its scope `/ivan/` contains every game's folder, which belong to the games' own workers.
  - `<head>` links next to the favicon: `<link rel="manifest" href="manifest.webmanifest?v=N">`, `<link rel="apple-touch-icon" href="apple-touch-icon.png?v=N">`, `<meta name="theme-color" content="…">`.
  - **The Android icon is drawn for Android, not just the favicon reused.** Next to `icon.svg` keep an `icon-maskable.svg`: the same artwork as a full-bleed square (no `rx`, no clip — the launcher applies its own circle/squircle mask) with everything that matters inside the central circle of radius ≈ 170 of the 512 viewBox (the launcher shows only about the middle two thirds). Bold shapes and strong contrast between the subject and the background — dark details (tracks, barrels, outlines) never sit on a dark background — so the icon stays clear at 48 px.
  - The PNGs are rendered from the SVGs, never drawn by hand: `bash tools/pwa-icons.sh <folder>` (`.` = the root gallery, writes into `assets/`) produces `icon-192.png`, `icon-512.png`, `icon-maskable-512.png` and `apple-touch-icon.png` (180 px, from the maskable SVG) with headless Chrome. Re-run it and bump the `?v=N` in the manifest and `<head>` whenever an icon SVG changes. Before committing, look at the maskable PNG cropped to a circle of two thirds of its size to make sure nothing is cut off.
